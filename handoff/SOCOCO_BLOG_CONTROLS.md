# SoCoco Blog 主页控件调研

日期：2026-08-29

## 调研范围

本笔记只记录 SoCoco 主页实际可见或在主页 HTML 中确认的控件，并与当前 Halfold's Blog 的已有能力做差异对照。它不是实现方案，也不代表这些功能已经获得加入 Blog 的决定。

参考来源：

- [SoCoco's Blog 主页](https://sococo.cn/)
- [SoCoco 的 Hexo 搭建博客文章](https://sococo.cn/2025/01/23/2025-01-23_blog_init/)
- 当前项目交接说明：`handoff/HANDOFF_V1.md`

## SoCoco 主页已确认的控件

### 1. 顶部全局控制

- 搜索入口：打开本地搜索框。
- Console 控制台入口：打开一个集中式功能面板。
- 昼夜模式切换。
- 移动端菜单按钮。
- Logo/站名回到首页。

### 2. 首页短内容条

主页顶部有一条可点击的短内容轮播区，展示几句即时记录或状态文字，点击后进入短文/essay 页面。它不是正式文章流，更像“最近在想什么”的轻量入口。

### 3. 推荐与分类条

文章列表上方有一条分类控制：`Recommend`、`All articles`、若干分类和 `More`。它把“推荐首页”和“按分类浏览”放在同一处，减少用户先去侧栏找分类的成本。

### 4. 文章卡片的状态控件

每篇文章卡片包含：

- 封面图；
- 分类标签；
- `New` 新文章标记；
- `Unread` 未读入口；
- 文章标签；
- 日期；
- 整张卡片可点击打开文章。

其中 `Unread` 需要浏览器端记录访问状态，属于有状态的交互，不只是一个装饰标签。

### 5. 分页与页码跳转

主页底部有页码、`Next` 和页码输入框，可直接跳到指定页。当前页面 HTML 中确认了 `toPageText` 和 `toPageButton`。

### 6. Console 控制台面板

控制台把多个侧栏信息和功能集中到一个可收起面板中，已确认包含：

- 标签云及每个标签的文章数量；
- 按年份分组的归档及文章数量；
- 昼夜模式入口；
- 侧栏显示/隐藏入口；
- 音乐开关；
- Useful links 外部链接卡片。

### 7. 右侧快捷工具组

主页 HTML 中确认了一个 `rightside` 工具组，包含：

- 设置/展开快捷工具；
- 模式切换；
- 侧栏显示控制；
- 返回顶部。

### 8. 站点信息卡

主页侧栏和下方信息区展示：

- 文章总数；
- 运行时间；
- 最后更新时间；
- 总字数。

这些信息由页面数据和运行时脚本共同提供。

### 9. 日历与时间倒计时

主页侧栏中有日历控件，以及一个“距离某个日期”的倒计时卡片；当前页面展示了距离除夕、今年剩余天数、本月剩余天数和本周剩余天数，并配有进度条。这属于个人站点氛围型组件，不是博客阅读的必要功能。

### 10. 音乐迷你控件

主页 DOM 中有音乐开关和底部音乐播放器入口，当前使用外部歌单播放器。主页上显示暂停状态，点击后由音乐开关控制播放区域。

## 没有列为“主页已启用控件”的内容

- 配置中的 `randomlink: false` 表明随机文章入口不是当前主页的主要启用功能，暂不把它当作已确认的主页控件。
- 当前主页配置显示评论关闭，因此不建议把“主页评论区”作为 Sococo 主页的既有控件照搬。
- PJAX、懒加载、外部音乐服务和主题内部脚本属于实现依赖，不应直接复制到 `halfold`。

## 与当前 Halfold's Blog 的差异

当前 Blog 已经具备或已预留：搜索、浅色/深色切换、文章/归档/分类/标签、相册、音乐页、读书架、统计页、留言页、友链页、站点信息页、文章分页、文章目录、灯箱、PWA 和评论接口。因此下面只列“新增价值”，不重复建议已有入口。

## 建议候选

### 第一梯队：适合优先讨论

| 控件 | 新增价值 | 复杂度 | 备注 |
| --- | --- | --- | --- |
| 首页短内容轮播/今日一句 | 增加轻量、非正式的个人表达入口 | 低-中 | 数据可先手工维护，不依赖第三方 |
| 首页站点信息小卡 | 让文章数量、字数、更新时间更容易被看到 | 低 | 可复用现有 `stats`/`sitetime` 数据 |
| 首页推荐/分类控制条 | 让首页在“推荐、全部、分类”之间切换更明确 | 低 | 当前已有分类条，可考虑升级信息层级 |
| 返回顶部 | 长页面阅读时减少滚动成本 | 低 | 独立按钮即可，不需要复制右侧整套工具组 |
| 首页文章封面与状态标签 | 提升文章列表的信息密度和可扫读性 | 低-中 | 需要明确封面缺省图与 `New` 的规则 |

### 第二梯队：有价值，但需要先确定交互边界

| 控件 | 新增价值 | 复杂度 | 主要风险 |
| --- | --- | --- | --- |
| 未读/已读状态 | 让访客知道哪些文章看过 | 中 | 需要 localStorage、状态失效规则和无障碍文本 |
| Console 功能抽屉 | 把标签云、归档、站点信息、友链等集中收纳 | 中 | 可能增加首页操作层级；移动端需要单独设计 |
| 桌面端侧栏收起 | 给内容区更多空间 | 低-中 | 不能影响移动端导航，也要记住用户偏好 |
| 日历/倒计时卡 | 增加个人站点的时间感和陪伴感 | 中 | 节日日期、时区和过期状态需要维护 |
| 音乐迷你播放条 | 让音乐页从“独立页面”延伸到全站 | 中 | 需要合法稳定音源、自动播放限制和移动端降级 |
| 页码输入跳转 | 文章很多时提高归档浏览效率 | 低 | 当前文章数量不大，暂时不是刚需 |

### 第三梯队：先不建议加入

- 直接复制 Sococo/Solitude 的 PJAX、主题内部 API 或外部播放器实现；当前主题结构不同，维护成本和缓存问题都较高。
- 为了“看起来像完整博客”增加大量外部链接、复杂控制台或第三方服务；这会让 Halfold 的简洁主页变得拥挤。
- 主页评论、随机推荐等当前没有充分需求或页面证据的控件。

## 初步结论

最值得先讨论的不是把 Sococo 的所有控件搬过来，而是从它的主页借鉴三种信息层级：

1. 轻量状态：短内容轮播/今日一句；
2. 快速浏览：推荐与分类条、文章封面和状态标签；
3. 低干扰信息：站点信息小卡、返回顶部。

如果后续要继续增强，再单独评估“未读状态”和“Console 功能抽屉”。日历倒计时、音乐迷你条属于风格功能，应在确定个人表达需求后再做。

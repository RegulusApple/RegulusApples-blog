## 1. 本轮修改方式

本轮采用“先区分页面范围，再拆结构，最后做交互和发布”的方式：

1. 先从用户提供的截图确认目标页面、主题模式、模块位置和移动端行为，区分首页、归档/分类/标签页和文章正文页，避免把文章页的需求误改到列表页。
2. 先读取现有 Hexo 模板和主题配置，确认模块是 EJS 生成、CSS 控制，还是由 `main.js` 运行时增强；没有通过重写整站或替换主题来解决局部问题。
3. 将页面结构变化放入对应布局：文章页侧栏由 `sidebar.ejs` 负责，文章正文由 `post.ejs` 负责；将全局视觉和响应式规则放入 `style.css`，将分类切换、音乐、目录状态和悬停行为放入 `main.js`。
4. 对“桌面冻结、移动端正常滚动”采用响应式分支：桌面 Contents 使用 sticky，移动端恢复普通文档流，不用 JavaScript 强行锁定页面。
5. 对目录采用运行时状态而非静态高亮：根据标题与视口的相交关系设置 `is-current`、`is-visible`，再由 CSS 控制模糊、显示和进入动画。
6. 每次结构或缓存相关修改后，递增 CSS/JS 查询版本，避免浏览器或 Service Worker 继续使用旧资源；最后执行构建、语法检查、差异检查和浏览器预览，再在用户确认后发布。

这套方式的核心是把“结构、视觉、行为、发布”分开，后续只需修改对应层，不要为了改一个模块复制一套页面。

## 2. 为什么需要多问确认

本项目大量修改来自截图和自然语言描述，同一句“改一下模块”可能意味着移动、删除、换色、冻结或新增交互。下一位代理继续工作时，应主动确认以下信息：

- **作用页面**：是首页、归档、分类、标签，还是文章详情；是列表页本身，还是从标签/分类点入后的文章列表。
- **修改范围**：只改深色模式还是明暗都改；只改一个模块、同类模块，还是全局组件；要删除、隐藏、替换还是仅改变样式。
- **交互结束条件**：悬停后状态是否保留、鼠标移开是否清除、点击后是否跳转、移动端没有 hover 时如何降级。
- **滚动与冻结语义**：“冻结”是 `position: sticky`、固定在视口，还是只在桌面端固定；移动端是否允许正常滚动。
- **参考图的优先级**：参考图是尺寸参考、颜色参考、布局参考，还是完整行为参考；不能默认把参考站点的所有模块搬过来。
- **发布边界**：本地预览是否满意、是否需要截图展示、是否已经确认可以上传；未确认前只做本地修改和验证。

多问不是拖慢修改，而是把容易产生返工的隐含决策提前显式化。尤其是“删掉”和“改成另一个模块”、“全局一致”和“只改深色模式”不能自行混用。

## 3. 当前已经修改的内容

### 3.1 文章详情页布局

- 删除文章页右侧的 `A NOTE TO SELF` 模块。
- 用 `Contents` 替代文章页原来右侧的 Archive 位置，并移动到左侧栏。
- 文章页左侧现在是三个模块：个人简介、`Now Playing`、`Contents`；右侧不再放辅助卡片。
- 扩大文章正文的可用宽度，使主内容适配“左侧栏 + 主文章区”的新比例。
- 删除文章顶部的“回到文章列表”入口和正文底部的 `READ NEXT / 也许你会喜欢` 区块；保留文章底部返回全部文章入口，并为其增加统一的悬停颜色和轻微上浮效果。
- 左侧模块标题改为左对齐；个人简介中的 `MYSELF` 和三个模块的 `01/02/03` 编号已移除。

### 3.2 Contents 目录交互

- `sidebar.ejs` 仅在 `page.layout === 'post'` 时渲染文章目录，其他页面继续显示 Archive 统计模块。
- `main.js` 从 `.article-body` 中读取 `h2`、`h3`，自动补齐标题 ID 并生成目录链接。
- 当前视口内的标题被标记为 `is-current`；进入视口的二级标题被标记为 `is-visible`。
- 未读标题默认模糊化；当前标题清晰显示；鼠标移入或键盘聚焦 Contents 模块时，整个目录清晰化。
- 二级标题默认不占位显示，只有对应正文标题进入视口后才出现，并通过 `toc-enter` 动画呼出。
- 目录链接使用平滑滚动；桌面端 Contents 使用 sticky，移动端在 `max-width: 1000px` 断点下恢复普通布局，保证手机可以自然滚动。

### 3.3 首页与分类切换

- 首页分类按钮不再只是跳转链接，而是具备实际筛选行为：点击分类后只保留对应分类的文章行，并同步更新文章数量和“暂无文章”状态。
- 当前筛选使用文章行的 `data-post-category` 与按钮的 `data-category-filter` 对应；后续新增分类时要同时检查主题分类配置和文章 Front Matter。
- 分类按钮、顶部导航和侧栏链接都保留明确的 hover/focus/active 状态，避免鼠标移开后继续残留不符合当前状态的样式。

### 3.4 深色模式与模块视觉

- 深色模式的“正在记录中”模块已按左侧其他模块的结构和边框逻辑统一，不再使用突兀的大块斜向渐变。
- 浅色模式的对应模块保持原有浅色渐变和布局，不因深色模式调整而被连带修改。
- 左侧卡片、导航按钮、分类按钮、归档年份卡片和文章交互链接统一使用颜色过渡、文字轻微上浮、箭头移动等反馈；鼠标离开后恢复默认状态。
- 归档模块改为参考 SoCoco 的统计卡片结构，包含年份文章数、全部文章数、Posts、Runtime、Last update 和 Word count 等信息；文章页不再显示它，非文章页仍可使用。

### 3.5 音乐模块和其他页面细节

- 左侧第二个模块重构为 mini `Now Playing`：只显示播放按钮、切换按钮、当前歌名、制作人/来源和状态，不显示完整歌单。
- 播放模块通过主题音乐配置读取当前曲目；有音频地址时启用播放按钮，没有地址时显示待接入状态。
- 相册入口保留为无下划线的查看相册链接，并增加统一的 hover 颜色和轻微位移动画。
- 站点品牌、导航分组、搜索入口、浅色/深色切换和既有页面的基础交互保持现有实现，不应因为本轮局部修改被整体替换。

## 7. 接手与继续修改规则

1. 先执行 `git status --short`，保留 `素材/`、`handoff/` 和其他未提交用户改动；不要使用 `git reset --hard`、`git checkout --` 或 `git add .`。
2. 视觉需求先定位到页面和主题模式，再定位模板；不要只凭截图猜测所有页面都要改。
3. 修改 Contents 时保留 `#article-toc`、`.toc-subitem`、`.is-current`、`.is-visible` 这些接口，避免 CSS 与运行时逻辑脱节。
4. 修改 sticky 或移动端行为时同时检查桌面、平板和手机，不要用固定高度掩盖正文溢出。
5. 修改 CSS/JS 后递增资源版本，并重新构建；若改了文章结构或页面路径，再运行项目已有的生成站点回归检查。
6. 用户说“确认”后才进入下一阶段；需要上传时先展示本地效果并确认发布范围。仅修改交付文档不等于需要重新部署网站。

### 10.2 月份模块“点击后不切换”的问题与修复

此前点击月份后，摘要内容已经写入 DOM，但模块马上被重置回月份视图。复现结果表明，点击后隐藏被聚焦的月份按钮会触发 `focusout`；旧逻辑把 `relatedTarget === null` 误判为鼠标已经离开模块，因此调用了重置。

当前修复已完成：

- `focusout` 只有在明确存在模块外的下一个焦点目标时才重置，不再因隐藏按钮产生的空焦点误触发。
- `mouseenter` / `mouseleave` 继续负责鼠标悬停和离开；离开有短暂延迟，并再次检查指针是否仍在模块内，避免模块内部切换时被误重置。
- 月份视图和月度时间轴共用同一个模块容器，切换时不跳转页面。
- 月度时间轴保留 `MMDD`、标题、简介和文章链接；按钮可用键盘操作。
- 模块正文设置最小高度，避免视图切换导致模块高度骤变，进而触发错误的离开判定。

涉及文件：

- `themes/halfold/layout/_partial/sidebar.ejs`：组合正式文章与预览草稿，按月份输出十二个月数据及月度条目。
- `themes/halfold/source/js/main.js`：月份点击、月度时间轴渲染、鼠标/焦点状态和离开后的复位。
- `themes/halfold/source/css/style.css`：默认虚化、悬停清晰、月份状态、内部时间轴和响应式表现。
- `themes/halfold/layout/layout.ejs`：当前资源版本号为 `style.css?v=25`、`main.js?v=16`，用于避免浏览器沿用旧资源。
